# 本地化：Brain 和 Eyes 接进 0.5 架构的对比（2026-10-19）

目标（负责人 10-19 定）：把这套架构里**合适的部分**换成本地的 DeskMind Brain（systemone，选择题模型）和 DeskMind Eyes（视觉定位），在**不降低效果**的前提下证明：成本下降、速度提升、隐私与安全更好。对照组是当前基准：动手模型和判官都在云端（DeepSeek V4.1 Flash）。

## 哪些部分能换、哪些不能（架构上的判断）

| 环节 | 现在谁做 | 能不能本地 | 依据 |
|---|---|---|---|
| 动手（理解要求、计划、调工具） | 云端大模型 | **不能**（现在） | 试验二：本地 7B 顶替 goal/plan/bind 1/30，3 次谎报（docs/0.5-decisions.md 结果 §试验二）。本地模型当执行者会让底线失守。 |
| 意图判官（这一步是用户要的吗） | 云端 | **能，做快档** | 选择题；契约：快档只能放行，不能单独否决；置信度低于门限升云端。 |
| 计划依据判官（这些证据能定理解吗） | 云端 | **能，做快档** | 同上。 |
| 完成核对（做成了没有） | 云端 | **能，做快档** | 同上；pass 以外的答案一律升云端。 |
| 视觉定位（没有辅助功能树的窗口） | 本地 Eyes（本来就是） | **已经本地** | 截图从不离开本机；云端方案得把截图发出去。 |
| 选哪份教程（候选由结构筛出后让模型挑一份） | 云端（老编排器的 choice 角色） | **能** | 选择题，老编排器就是为 Brain 设计的这一问；运行时这边候选直接列给动手模型读，没有单独一问。 |
| 教程的学习与修订、文本改写、上下文压缩 | 云端 | 不能 | 是生成任务，不是选择题；Brain 的接口是选择题。 |

模型调用点的完整清单（`grep ask(` 全库）：判官三问（judge.ts）、选教程（agentskills.ts）、写教程 / 修订教程（teach.ts、library.ts ×2，生成）、文本改写（transform，生成）、动手循环（pi-agent-core，生成）、模型连通性检查（app.ts，一问一答）。**能换成 Brain 的就是前两类，都换了**；Eyes 换的是视觉定位，已全本地。范围之外的（更强的本地生成模型做动手）不在这份对比里。

所以「尽可能本地化」在这个架构里 = 三类判官问题走本地快档 + 视觉全本地；动手仍在云端。下面的数字就量这两件事。

## 方法

- 同一套代码（harness @ 最新 0.5-runtime）、同一个动手模型（DeepSeek V4.1 Flash）、同一批题、同一评分：
  - **A 基准**：判官全在云端（DeepSeek）。
  - **B 本地化**：Brain 做判官快档（门限 0.9），云端做慢档。
- 练习场 40 题（模拟桌面邮件任务，按应用真实状态判分）和检查集 105 题（7 类 × 15：单步、换工具名、多步、界面、有歧义、做不到、学技能）。
- 量：对的比例 / 最低类 / 做错 / 谎报（效果）；云端调用次数、token、按挂牌价折算的美元（成本）；秒/题（速度）；判官问题里材料没出本机的比例（隐私）。
- 价格口径：DeepSeek V4.1 Flash 标准时段挂牌价 $0.30 / $1.20 每百万输入 / 输出 token（第三方聚合页一致，官方页未直接取到）。

## 结果

### 练习场 40 题（模拟桌面的邮件任务：看、删、加旗标、回复；按应用真实状态判分）

`runs/gym-ds-flash`（A）vs `runs/gym-local-B-brain-judge`（B），同一代码、同一动手模型。

| | A 云端判官 | B Brain 快档 | 变化 |
|---|---|---|---|
| 通过 / 谎报 / 越权 / 碰用户窗口 | 40/40 / 0 / 0 / 0 | **40/40 / 0 / 0 / 0** | 效果不变 |
| 卡/题 | 1.7 | 1.9 | +0.2 |
| 判官问题数 | 226 | 208 | |
| 其中本地（Brain）定的 | 0 | **132（63%）** | |
| 判官云端调用/题 | 5.7 | **1.9** | **−67%** |
| 判官云端 token 入/题 | 4954 | **2099** | **−58%** |
| 判官云端等待 秒/题 | 14.9 | **6.3** | **−58%** |
| 秒/题（整题） | 27.1 | **20.9** | **−23%** |
| 判官材料出本机 字符/题 | 11213 | **4737** | **−58%** |

解读：界面类任务的判官材料短（窗口元素、几行文字），Brain 能定六成多；放行的 132 次按应用真实状态没有一次放错。云端判官的 token 占整题云端 token 的一半以上，所以判官本地化直接把这部分砍掉近六成，整题快了近四分之一；出本机的材料（用户原话 + 窗口内容）少了 58%。

`runs/local-A-cloud-judge` vs `runs/local-B-brain-judge`，同一代码、同一动手模型、同一模拟用户。`python3 scripts/compare-local.py runs/local-A-cloud-judge runs/local-B-brain-judge`。

| | A 云端判官 | B Brain 快档 | 变化 |
|---|---|---|---|
| 平均正确率 / 最低类 | 88% / 33% | **90% / 40%** | 持平（差异在噪声内，见下） |
| 做错 / 谎报 / 越权 | 8 / 8 / 0 | 6 / 9 / 0 | 持平；两边没对的题是同一批口径题 |
| 打扰（卡）总数 | 122 | 121 | 持平 |
| 判官问题数，其中本地定的 | 419，0 | 426，**165（39%）** | |
| 判官云端调用/题 | 4.30 | **2.69** | **−37%** |
| 判官云端 token 入/题 | 5152 | **3973** | **−23%** |
| 判官云端等待 秒/题 | 9.2 | **6.9** | **−25%** |
| 美元/题（动手 + 判官，挂牌价） | $0.00642 | **$0.00568** | **−12%** |
| 秒/题（整题） | 26.5 | 27.2 | +3%（噪声） |
| 判官材料出本机 字符/题 | 10865 | **8510** | **−22%** |

按类：有歧义 93% → 100%，做不到 33% → 40%，其余五类两边一样（单步、换名、多步、界面 100%，学技能 87%）。两边没对的题几乎重合：3 道崩溃题 + cannot-000/009/012/013「用户当场改口 / 你看着办」（Q25 已定按用户的话做，标准答案还没改）、2 道诚实的做不到（010/014）、学技能 2 道。**本地化没有引入新的错误类型。**

### 判官校准（`scripts/judge-calibration.py`：Brain 每次升级的答案和云端最终答案配对）

| Brain 的答案 | 置信度 | 和云端一致 |
|---|---|---|
| 放行 | 0.8（低于门限） | 23/25（练习场 18/27） |
| 否决 / 证据不够 | 0.9 | 16/151 |
| 否决 / 证据不够 | 0.8 | 7/78 |

- **门限 0.9 不能降**：0.8 的放行在练习场上云端只同意 18/27，降门限会放错。
- **Brain 的否决没有信息量**：检查集上意图题被云端推翻 88/113、核对题 97/99。契约「快档不能单独否决」就是为这个——否则这些正确动作全被拦。
- Brain 一题本地 0.2–1.3 秒，所以它否决时多花的时间小；整题时间持平就是这么来的（练习场快 23% 是因为那里它放行多）。
- 它放行的 165（检查集）+ 132（练习场）次，按文件树 / 应用状态的评分没有一次放错。

### 影子核对：Brain 每次自己定的答案，云端同不同意（直接量「安全有没有降」）

上面的「放错 0 次」是按结果评分推断的。为了直接量，加了判官的影子模式（`DESKMIND_JUDGE_SHADOW=1`，`scripts/compare-local.py` 的「影子核对」行）：Brain 自己定的每个答案，再问一次云端，只比较不采用。

| | 练习场 40（界面） | 检查集（文件，C 组） |
|---|---|---|
| Brain 自定的答案里云端同意的 | **100/133（75%）** | **142/149（95%）** |
| 意图题 | 26/56 | 36/38 |
| 计划依据题 | 48/51 | 105/110 |
| 核对题 | 26/26 | 1/1 |
| 不同意的是什么 | 云端说「证据不够」27、「不一致」3（意图）；读法「说不清」3 | 读法「说不清」5、「证据不够」2 |

**D 组（练习场 40，按一致率路由）**：判官按「问题种类 × 对象类型」记录影子一致率，比较满 10 次仍低于 90% 的种类不再先问 Brain（每 20 题探一次）。结果：40/40，谎报 0，**影子一致率 93%（76/82）**，本地占比从 66% 降到 39%（窗口上的意图题在比较 10 次、同意 6 次后全部回到云端；核对题 22/22 一致，留在本地）。也就是说界面任务上的宽松可以**不靠训练、靠测量**关掉，代价是本地占比和速度收益让出一部分。

怎么读：
- 文件任务上 Brain 的放行和云端几乎一致（96%）。
- **界面任务上意图题只有 46% 一致**：Brain 放行了 30 次云端不会放行的动作——27 次云端会说「证据不够」（按契约那会落到用户同意卡，不是拒绝），3 次云端会说「不一致」（会被拒）。这 30 次按应用真实状态都没造成错误效果、也没越权（40 题 0 谎报 0 越权），但「Brain 放行 = 云端也会放行」在界面任务上**不成立**，之前只凭结果说「0 放错」说过了。
- 所以本地化在**安全**上的准确表述是：底线（不谎报、不越权）由执行层结构守住，影子核对证明本地判官没有让这 40 + 105 题里任何一个动作越过底线；但它比云端判官**宽松**——界面任务上四分之一的放行云端会要求先问用户。这是可改的：这 30 次的材料和云端答案就是训练标签（见下一步 1）。

### 自适应路由（C 组）

Brain 对「核对」题几乎只会说不够（B 组 2/99），自适应路由在问了 8 次之后不再问它这类题（每 20 题探一次）：检查集 105 题里跳过 **90** 次。C 组的效果：平均 90%、最低类 47%、做错 4、谎报 7、卡 116（A 组 88% / 33% / 8 / 8 / 122）——和 B 组一样，在噪声和口径题之内，没有因为跳过而变差。省的是 Brain 每题 0.2–1.3 秒，约 0.1–0.9 秒/题——和预期一样小，但是白拿的；本地占比不变（39%），因为跳掉的本来就不会在本地定。C 组因为开了影子模式（每个本地答案多一次云端调用）成本和速度数字不能直接比，成本 / 速度看 B 组。

### 竞速（E 组）：快档和云端同时问，谁先定用谁

文件任务上 B 组速度持平的原因是 Brain 否决时的时间白花了（先问它、再问云端）。E 组改成**竞速**：云端判官和 Brain 同时发出，Brain 高置信放行就立刻采用并中止云端请求；Brain 否决或拿不准时云端的答案已经在路上，一秒不多等。路由表沿用 D 组学到的（窗口上的意图题不问 Brain）。

| | 检查集 105：A 云端判官 | **E 竞速** | 变化 |
|---|---|---|---|
| 平均 / 最低 | 88% / 33% | **91% / 40%** | 持平偏好 |
| 做错 / 谎报 / 越权 | 8 / 8 / 0 | 4 / 7 / 0 | 持平 |
| 打扰（卡） | 122 | 106 | −13% |
| 本地定的判官问题 | 0 | 123（32%） | |
| 判官云端调用（回答了的）/题 | 4.30 | **3.01** | **−30%** |
| 判官云端等待 秒/题 | 9.2 | **6.9** | **−25%** |
| 美元/题（含判官，挂牌价） | $0.00642 | **$0.00559** | **−13%** |
| 判官材料出本机 字符/题 | 10865 | 9163 | −16% |
| **整题 秒/题** | 26.5 | **23.1** | **−13%** |
| 竞速中中止的云端调用/题 | 0 | 0.91 | 计费与否看服务商 |

练习场 40（E）：40/40，谎报 0，22.4 秒/题（A 27.1，B 20.9），本地占比 37%（路由把窗口意图题交回云端后）。

**重复一遍（E2，同配置再跑检查集 105）**：91% / 最低 60%，做错 2、谎报 6、越权 0；判官云端调用 −26%，判官等待 −29%，美元 −9%，出本机 −15%，整题 **−5%**（26.5 → 25.2 秒）。两次合看：文件任务整题 −5%～−13%，判官调用 −26%～−30%，美元 −9%～−13%——方向一致，幅度随云端当时的延迟波动。

读法：文件任务的速度从持平到 **−13%**，是本地化在文件任务上第一次有速度收益；代价是中止的云端请求（0.9 次/题）服务商可能照样计费——成本列只按回答了的调用算，真实省钱可能比 −13% 少一点。

## 结论（五组：A 全云端判官；B Brain 快档；C + 自适应路由 + 影子核对；D 按一致率路由；E 竞速）

1. **效果不降**：练习场 40/40 对 40/40；检查集 A 88% / 最低 33% → B 90% / 40% → C 90% / 47%，没对的题是同一批口径题（崩溃题、「用户当场改口」、诚实的做不到）；谎报 8 → 9 / 7，越权 0 → 0，打扰持平。这由契约保证：本地只能放行、放行要 ≥0.9 置信、否决和拿不准一律升云端。
2. **成本下降**：判官的云端调用 −26%～−37%（文件，E2 / E / B）/ −67%（界面，B），判官 token −15%～−58%，按挂牌价整题 **−9%～−13%**（文件）。动手模型的那部分不变——它不能本地化（试验二），而它是成本的大头，所以整题只省一成多；判官那部分省了一半。
3. **速度**：界面任务整题 **−17%～−23%**（E / B）；文件任务 B 组持平、竞速后 **−5%～−13%**（两次运行）——快档否决不再占时间。
4. **隐私**：判官材料（用户原话、窗口内容、文件内容）出本机 −22%（文件）/ −58%（界面）；截图全量留在本机（Eyes，音乐示例一次 22 张 9 MB）。
5. **安全**（影子核对直接量）：Brain 自己定的答案云端同意率文件任务 **95%**、界面任务 **75%**；不同意的在界面任务上集中在意图题（30/56：云端会先问用户 27 次、拒 3 次）。这些放行按应用真实状态**没有一次造成错误效果或越权**——底线由执行层守住，不靠判官。**按一致率路由**（D 组）把这个口子用测量关上：窗口上的意图题回到云端，界面任务的一致率 75% → **93%**，代价是本地占比 66% → 39%。生产里影子比较按比例抽样（见下），路由表随用随学。

6. **「尽可能本地化」的边界**：能换成 Brain 的（选择题：判官三问、选教程）和能换成 Eyes 的（视觉定位）都换了；动手模型不能换成 Brain（它只会选不会写），换成本机 7B 也不行（L1：30 题 5 对、3 谎报）。所以这套架构今天的「最本地」= 动手在云端 + 判官本地快档（按一致率路由 + 竞速）+ 视觉全本地；再往前一步是给 Brain 训练这次收集的判官样本（界面意图题的 30 条分歧）。

一句话：判官本地化在**不降效果、不越底线**的前提下，把判官的云端调用砍了三到七成、整题快了一到两成（文件 −13%、界面 −23%）、出本机的材料少了两到六成；代价是界面任务上本地判官比云端宽松（多放行、少问），要用这次收集的 30 条分歧样本去训。动手模型仍在云端，所以总成本和总时间的改善是判官那一份的比例，不是数量级。

### 给 Brain 的训练样本（已产出）

判官多了 `judge.sample` 事件（`DESKMIND_JUDGE_SAMPLES=1`）：每道两档都答过的题（升级的，或影子比较的）带提示词、选项、Brain 的答案和置信度、云端的答案。`scripts/judge-samples.py` 汇成 JSONL。练习场 40 题一遍：**204 条（意图 99、计划依据 65、核对 40；两档不一致 78 条，其中意图题 Brain 放行而云端说「证据不够 / 不一致」57 条）**。文件在 `runs/judge-samples-gym.jsonl`（727 KB，不进仓库），检查集再跑一遍同样的开关能再得 ~400 条。给 brain 仓库做微调就是这份：输入是提示词，标签是云端的答案。

## 下一步（按收益排）

0. **把界面任务上的分歧样本喂给 Brain 训练**（样本已产出，见上）（Brain 放行、云端说问用户 / 不一致）：影子模式下判官日志里有材料和两边答案，这是最便宜的安全改进；目标把界面任务的同意率从 75% 提到 90% 以上。提门限没用——离线算过：界面意图题上 Brain 的分歧和置信度无关（≥0.90 的一致率 18/40，≥0.95 的 8/16，都是一半），门限 0.95 只会把放行砍到 16/56 而一致率不变。这是系统性的判断差异，只能靠训练。
1. **让 Brain 在文件任务上放行得更多**：它现在对「核对」题几乎只会说不够（2 次放行 / 99 次升级），对意图题放行 32 / 升级 113。这是训练数据的事（核对题的判据是一段长规则 + 目录版本 + 回执），不是接线的事——给 Brain 的训练集加上这两类题（判官日志里现成有云端的答案可当标签：检查集 426 + 练习场 208 道，带材料）。目标：文件任务的本地占比从 39% 到 60% 以上，整题也能快起来。
2. **按题型自适应路由**（小改动）：判官记住每类问题 Brain 的放行率，低于某个比例就不先问它——省的是它否决时那 0.2–1.3 秒，文件任务能回到略快于云端。
3. **Eyes 已经在本地**，没有云端对照可比；它的收益是「没有辅助功能树的应用能做」（网易云音乐那条）而不是省钱。
4. **动手模型本地化**仍不做：试验二的结论没变；等更强的本地模型再测，方法和这次一样（同一代码、同一批题、同一评分）。

### Eyes：像素模式任务的截图留在本机（量）

没有云端对照（这套架构从没把截图发出去过），所以量的是「本地化省掉了多少外发」：首页示例「打开网易云音乐，搜索张悬的《宝贝》并播放」一次运行，驱动对那个窗口截了 **22 张图，共 9.0 MB**（hands 轨迹 `runs/do-20261019-002515/obs`，每张约 400 KB，1059×752），OCR（macOS Vision，本机）和定位器（Eyes，127.0.0.1:18851）全在本地处理。换成云端视觉模型的设计，这 22 张就是 22 次上传（每张约 1–1.5k 图像 token，音乐库、联系人、聊天这类窗口内容随图出去）。像素模式下每一步都要一张，所以任务越长外发越多；本地化在这里是**全量**的，不是比例。

### Eyes 对云端视觉模型：同样的截图、同样的问题（`scripts/eyes-vs-cloud.py`）

音乐示例那次运行的 20 张截图 × 3 个定位问题（搜索框、关闭按钮（面板/弹窗）、播放按钮），本地 Eyes（127.0.0.1:18851）对 doubao-seed-evolving（带图，关推理）：

| | Eyes（本地） | 云端视觉模型 |
|---|---|---|
| 每张截图（3 问）耗时 | 6.4 秒 | 6.4 秒（3 次串行调用） |
| 费用 | $0 | **$0.087 / 20 张**（90k 图像 token；≈ $0.0043/张，像素模式一步一张） |
| 上传 | 0 | **9.0 MB**（整张窗口：音乐库、账号名、聊天都在图里） |
| 两边都定位了的 60 个点里，相距 ≤ 窗口宽 3% 的 | 47/60（78%） | |

怎么读：速度打平，本地省的是钱（一步像素任务 ≈ 半分钱）和整张截图的外发；78% 的一致说明两边定位大体相同，剩下 22% 谁对谁错要看点下去有没有反应（驱动本来就这么做：「点了没变」就标为没有这个控件）。隐私上这是全量：像素模式的任务越长，云端方案外发的截图越多。

### 动手模型本地化：在新运行时上再测一次（L1 组）

「尽可能本地化」的边界在哪，不能只引用试验二（那是老编排器的三个角色）。这次把本机自带的 `mlx-community/Qwen2.5-7B-Instruct-4bit` 通过 `mlx_lm.server` 接成**动手模型**（工具调用能用），判官 Brain 快档 + DeepSeek 慢档，跑检查集的单步和界面两类（30 题，DeepSeek 同题 30/30）：

| | DeepSeek Flash 动手 | 本地 7B 动手 |
|---|---|---|
| 单步 15 | 15 | **2** |
| 界面 15 | 15 | **3** |
| 谎报 / 做错 / 越权 | 0 / 0 / 0 | 3 / 1 / **0** |
| 打扰（卡） | — | 64 |
| 秒/题 | 14.9 | 61（20.6 次调用/题，多数「轮数用完」） |

读法：7B 在工具循环里原地打转（16/30 轮数用完），该问的不问、不该问的问（64 张卡）；越权仍是 0——底线由执行层守住——但 3 次谎报说明云端核对在动手模型很弱时也会被骗（它的证据是回执和现状，动手模型胡乱操作后现状未必和要求矛盾）。**结论没变：动手模型不能换成 Brain**（Brain 只会选不会写），也换不成本机现有的小生成模型；边界是实测的。更强的本地生成模型（30B 级）负责人 10-19 定为不在本份对比范围内，方法留着（`local` 供应商 + `--config local-<model>`）。

## 隐私与安全的定性部分

- 判官问题的材料是最敏感的：用户原话、窗口里的文字、文件内容、目录列表。走 Brain 的那部分不出本机。
- Eyes：没有辅助功能树的应用（网易云音乐这类）只能靠截图；截图留在本机，定位器在 127.0.0.1。
- 不变的部分：动手模型看到的内容仍然出本机（设置卡里已明说）；底线（不谎报、不越权、随时可停）由执行层结构保证，与模型在哪无关。
- 安全上的新约束：快档不能单独否决（10-18 探针里 Brain 有把握的否决是错的），所以本地化不会让该拒的动作被放行——放行需要快档高置信，而放错一次就是一条记录。
