# 同意凭证：交互规格（草案，10-18 夜，对应试验三）

机制已经实现（`src/executor/consent.ts`、`executor.ts`，测试 `test/executor.test.ts`、`test/runtime.test.ts`）。这份规格写的是 app 和用户看到的那一面，交负责人定。

## 一、一次「同意计划」覆盖什么

计划卡列出每一步：目的、涉及的对象（窗口 / 标签页 / 文件）、后果类别。用户点「可以」之后：

| 步骤的类别 | 签什么 | 之后怎么样 |
|---|---|---|
| 只读、创建、改任务自己的东西 | 不签 | 直接做，结果卡上列出来 |
| 改用户的东西 | 每个对象一张 **object** 档凭证（本次任务、这个对象、最高到「改用户的东西」） | 这个对象上的后续动作不再打扰 |
| 往外发 | 不签 | 到那一步单独弹一张动作卡，带实际内容（收件人、正文、金额），用户点了才签一张 **action** 档凭证，只能用一次 |

计划里没列、执行时才碰到的用户对象：当场弹动作卡（action 档）。用户在动作卡上选「这一步不要」，模型得到的是拒绝原因，换做法或如实结束；选「先别做了」整个任务取消。

**为什么往外发不随计划签：** 发出去的内容在计划时还没写出来；用户同意的应该是「这封回复」而不是「某封回复」。

## 二、三档范围在卡片上怎么呈现

| 档 | 卡片 | 文案样例 | 有效期 | 用几次 |
|---|---|---|---|---|
| action | 动作卡 | 在 信鸽「收件箱」 点「发送」（这会把内容发出去）\n回复内容：收到，谢谢 | 5 分钟 | 1 次，用完即废 |
| object | 计划卡（隐含）；结果卡上写明「改动了你的：信鸽 收件箱」 | 我打算这样做：1. 打开林晓的邮件并回复（信鸽 收件箱）——改你的东西 | 本次任务（默认 1 小时） | 本次任务里不限 |
| rule | 动作卡上多一个选项「以后这类都不用问」；app 的设置页能看到、能撤销 | 以后关掉我的邮件窗口不用问 | 长期，直到撤销 | 不限 |

卡片上不出现「凭证」「签名」这些词。用户看到的是动作和后果；凭证是 app 和执行层之间的事。

## 三、签名要不要指纹

建议：**动作卡和计划卡不要指纹**，点一下就是同意（私钥在 app 的钥匙串里，签名对用户透明）。只有 **rule 档** 和「往外发且金额 / 收件人涉及钱」这两类，app 可以要求 Touch ID，由 app 的设置决定，执行层不关心。

理由：指纹的意义是防止别人替用户同意；一次性的动作卡本身就在用户眼前，再要指纹只会让用户养成无脑按的习惯。

## 四、有效期

- 挑战（执行层出的题）：5 分钟。超时未答，动作按「没同意」处理，模型收到的是拒绝。
- action 档：5 分钟，且只能用一次。
- object 档：本次任务结束即作废（执行层按 task id 校验），另有 1 小时上限防止任务挂死。
- rule 档：长期；app 列表可撤销；撤销后执行层下次 begin 时不再带入。

## 五、被拒绝和过期时界面上怎么显示

| 情况 | 执行层的回执 | app 显示 |
|---|---|---|
| 用户点了「这一步不要」 | `refused`（by: user） | 步骤列表里这一步打叉，写「你不让做」；后面模型换做法或结束 |
| 挑战过期（用户没答） | `refused`（by: executor, why: expired） | 「等你太久，这一步没做」；任务结束时结果卡说明哪些没做 |
| 凭证不匹配（动作变了、对象变了、类别升高了） | `needs_consent`，带新挑战 | 再弹一张动作卡；旧卡自动作废 |
| 用户点了「先别做了」 | 任务 `cancelled` | 结果卡：「已停下，没有发出任何东西 / 改动了这些：…」 |
| 锁屏、app 停止 | `environment` / `stopped` | 「屏幕锁了，停在第 n 步」/「已停止」；往外发的步骤如果已经点了发送但没读回结果，标「可能只做了一半」 |

## 六、要负责人定的

1. 第三节的指纹范围。
2. object 档的 1 小时上限要不要。
3. rule 档的撤销入口放在哪（设置页 / 结果卡上的「取消这条规则」）。
4. D20：用户窗口里只改视图状态（选中一行、切标签）算不算改用户的东西。按最严算的话，只读任务也会弹一张卡（练习场 ask 类平均 1–2 张）。
